## Notes

1. Observation (not in any AC): after a failed Register the inline error stays visible while the user edits the field. E.g. the path error "Folder `src` was not found." was still displayed after the path had been changed to `app-a\sub` and the note appeared, until the next Register click. AC-16 only says validation runs on Register, so this was recorded, not failed.
2. E15: the app-a `sub` directory timestamp change (…812549 → …973037) is unexplained by that run; no causal claim is made for it. The only valid no-write result is the app-c rerun (b): its baseline had to be re-taken because `sub`'s timestamp changed once between snapshots 1 and 2 with no registration in between (observed, cause not established), and after settling, the post-register snapshot was identical. Caveat: one post-register snapshot only.
3. Launch method: `npm run tauri dev` in a non-PTY service shell made `beforeDevCommand` (Vite) exit; it was rerun in a PTY. The first launch (without debug port) is where migration 2 ran on the F01 database; M1 was read after it and again after later launches. The Alt-key / Tab behaviours of F01 were not repeated.
4. Registered project rows are test data and remain: ids 1 "App A" (`...\app-a`), 2 "App A Sub" (`...\app-a\sub`), 3 "app b" (`...\app-b`, pinned = 1), 4 "App C" (`...\app-c`). F02 has no delete. Restore option: copy `devshelf.sqlite3.f01-backup` back over `devshelf.sqlite3` (F01 state, user_version 1) with the app closed.
