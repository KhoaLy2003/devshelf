# F05 Workspace restore: E2E results (Phase 2 Step 5)

- Spec: `docs/specs/workspace-restore/spec.md` (AC-xx).
- Run: `npm run tauri dev` from the project root (real app, Windows, dev build). Cargo printed "Finished `dev` profile ... in 0.33s", so the existing `target\debug\devshelf.exe` was run without a rebuild.
- UI driving: WebView2 remote debugging port 9222 (`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`, set only in the dev-server shell). Chrome DevTools Protocol `Input.dispatchMouseEvent` (real mouse press/release at element centers), `Input.dispatchKeyEvent` (Ctrl+A, Delete, ArrowDown, Enter for native selects) and `Input.insertText`. Page reload used CDP `Page.reload`. Navigation between screens was by clicking the sidebar link and list rows. DOM reads (innerText, button disabled state) used `Runtime.evaluate`. A `MutationObserver` recorded the Restore button label and panel changes; `Network.enable` recorded IPC requests for the double-click row.
- Native dialogs (Browse file..., Browse folder...): a PowerShell script (Win32 `EnumWindows`/`EnumChildWindows`) found the `#32770` dialog owned by devshelf.exe ("Open", "Select Folder"), wrote the path into its `Edit` control with `WM_SETTEXT` and pressed button id 1 with `BM_CLICK`. All three dialogs worked on the first attempt.
- DB reads: read-only (`bun:sqlite` with `readonly: true`).
- Backup of the pre-F05 file (user_version 4): `%APPDATA%\app.devshelf.desktop\devshelf.sqlite3.f04-backup`, SHA-256 `1412c3a806ee833d5feaacd518b5ab65e03d64ebd33beb22b99ad5bd3ea1f395` (identical to the live file's hash at that moment).

- Workspaces created in the UI: `F05 Main` (items: 1 `gone\x.txt` file, Windows default; 2 `exe-test` folder, Notepad++ with no executable path; 3 `ok\readme.txt` file; 4 `ok\sub` folder), `F05 Relink` (1 `gone\x.txt`; 2 `exe-test\mismatch` folder, later swapped to a file on disk), `F05 Empty` (no items).
- Windows opened by Restore: one "readme.txt - Notepad" window (hwnd 131634, pid 22832) and one "sub - File Explorer" window (hwnd 591368, explorer pid 1512). A window-less Notepad helper process (pid 15056, later 11624) appeared after Restore and was gone after the readme window closed; it was not killed by me.
- "Reload" means a WebView reload plus a DB read, not an app restart.
- No source files were modified. Dev-mode only.

## Observations (not failures)

- A repeat Restore of items already open in Notepad or Explorer produced no new top-level window (existing window reused). Relaunch is therefore not proven by window handles; the opened count and `last_restored_at` both updated.
- AC-01 disabled state was read from the button's `disabled` property (true); a click on the disabled button was not tried.
- The "All 2 items opened." line in R25/R26 came from a new Restore click after Apply (the cell clicked Restore between the two reads).
- Real app restart (AC-62/63 across a relaunch): NOT RUN.
- Run used the dirty working tree on HEAD `eedf4c5` (F05 changes uncommitted, `restore.rs` and the spec folder untracked). The spec header still reads draft.
- After Relink Apply, the row keeps the old "Path not found." / "Now a file, not a folder." line next to "Relinked. It will open on the next restore." until the next Restore. R11/R25 pass on their own criteria (notice shown, row stays, DB updated); the stale reason is logged separately as R28 (FAIL).
- Relink offers only the Browse button for the stored kind (file: Browse file...; folder: Browse folder...).
- The detail header says "N items, reopened in this order." (F04 copy).
- Persistence checks used a WebView reload plus DB reads; no app restart was run.
