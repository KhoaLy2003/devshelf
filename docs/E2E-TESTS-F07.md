## BLOCKED and observations

- N07 (AC-22, and the failing-save branch of AC-23, and AC-21's "Couldn't save." state): not exercised against the real app. A webview-level fault is not a faithful failure: the Fetch failure falls back to postMessage and the save succeeds, and the `invoke` patch did not intercept. Rust failure paths are covered by the P4 unit tests only. Note: the live UI of the error state, the text-kept behaviour and the Retry button were never seen.
- N11b: with the key missing, a note cannot be deleted from the UI (no Delete control on the "Note unavailable" page). The spec does not require one, but it leaves permanently unreadable notes in the list until F12. Reported only.
- The key is created on "New note" (`notes_create`), earlier than the first body save; both fall under "first use" in AC-31.
- AC-24 (one save in flight at a time) was not tested live.
- A blank title is stored as the empty string; the list label "Untitled note" for a blank title was not viewed.
- Real app restart was not run; N13 used `Page.reload`.
- The `localhost` resource 404 / ERR_FAILED console entries came from the WebView (a missing static resource and the reload), not from notes code.
