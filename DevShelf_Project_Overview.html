DevShelf
PRODUCT KICKOFF · v0.1 · 10 OCT 2026
Local-first developer productivity

A home for projects, configs, secrets, and notes.

DevShelf is a Windows desktop app that helps developers organize project files and restore working sets, catalog environment configuration, securely store credentials, and keep private technical notes—while continuing to use their preferred external editors.

External-editor workflow

DevShelf stores file references and launch preferences. It opens a file in Notepad++, VS Code, or the selected application; it does not attempt to replace the editor or promise restoration of unsaved buffers and internal tab state.

Proposed technology

A compact desktop architecture designed for offline operation and maintainability.

Desktop
Tauri 2 — Windows packaging, native capabilities, controlled IPC.
Frontend
React + TypeScript + Vite — feature-based UI; Tailwind CSS and a reusable component system.
Native services
Rust — validation, application use cases, filesystem access, editor launching, and all Vault cryptographic operations.
Local database
SQLite — project/workspace metadata and encrypted records; no database server required.
Security
Argon2id + authenticated encryption — proposed design subject to security review and use of maintained cryptographic libraries.

Security is a product requirement

Protect data at rest and reduce accidental disclosure during use.

Vault design principles

  • Derive a key from the master password with Argon2id.
  • Use a random Vault Data Key, wrapped by a key derived from the password.
  • Encrypt secrets and private note content before database persistence.
  • Keep crypto operations in Rust; do not persist keys or plaintext in frontend storage.
  • Mask by default; reveal/copy is explicit and requires an unlocked Vault.
  • Lock on demand, inactivity, and app exit; clear app-level decrypted caches.

Security boundaries

  • No secrets or note bodies in logs, telemetry, error messages, or audit events.
  • Plaintext `.env` export is explicit, warned, and never silently overwrites.
  • Clipboard clearing is best-effort; clipboard history and paste targets cannot be controlled.
  • Least-privilege Tauri permissions; no generic arbitrary-command execution.
  • Encrypted backup/restore must be tested before internal rollout.
  • Host malware or a compromised user account is outside the Vault's complete protection.

What is in—and out—of the MVP

Included

  • Project registry and cross-project workspaces
  • Config-file references and environment labels
  • External editor profiles and quick open
  • Project-linked private notes stored outside project roots
  • Encrypted local Vault with explicit reveal/copy flows
  • Local-only operation and tested backup/restore

Deferred

  • Embedded code editor or terminal
  • Automatic secret injection into processes
  • Automatic configuration rewriting/deployment
  • Team sharing and centralized remote secret service
  • Cloud sync and multi-device conflict resolution
  • Repository-wide content indexing by default

Definition of success

The app is ready for internal rollout when these outcomes are demonstrated, not merely implemented.

Fast to resume

A developer can register several projects, save a cross-project file collection, restart DevShelf, and reopen the collection without manually navigating each folder.

Safe by default

Project files are never silently changed; Vault records and private notes are encrypted at rest; plaintext access is explicit and no protected content is logged.

Recoverable

Missing paths are repairable, migrations are tested, and an encrypted backup can be restored and unlocked in a clean environment.

Kickoff decisions required

Confirm product name and supported Windows versions; approve the Vault cryptographic design and recovery policy; decide which metadata is encrypted; define auto-lock and clipboard behavior; set performance targets; and confirm internal handling rules for production credentials.
